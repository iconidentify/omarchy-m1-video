# Paired command and reference capture (#71)

AI disclosure: generated by AI. This is experimental maintainer capture tooling;
there is no installer, boot change or support-count claim.

`capture.py` supervises one ordinary decoder child within the driver's exclusive
hardware guard. The child blocks on a pipe until both recorders are armed for its
PID and the same run. A parent-death signal kills it if supervision disappears.
The actual waited decoder status remains authoritative even when v4l2-tracer
returns a misleading raw wait status. Both partial captures are preserved on an
error; a new run requires initially OFF recorders and no contexts.

`measure.py` uses ioctl tracing for **both** off and on modes; off/on refers only
to the two kernel recorders. It validates all 300 exact frame hashes against the
accepted campaign and the matching off run, all successful ioctl controls and
request lifetimes, every output/POC association, the complete paired reference
history and all selected command words in pictures 24–34 against the pinned C.
`compare.py` maps every named copied field to the same-run returned controls;
flag numbers come from the hash-verified kernel UAPI, not enum ordering.
