links for a process in one list expression, then skips that process on any
OSError. An unrelated closing FD can hide a persistent decoder holder. Audits
before/after that scan do not fix the race. The experiment's read-only root
observer now handles each FD separately, ignores vanished individual FDs and
propagates other inspection errors. It matches character-device numbers and
retains established topology/fault rules. The production guard file is unchanged.
The reviewer inspected two synthetic regressions; the parent executed both
successfully under tools/bounded-build (73 ms, 19.4 MiB), without hardware access.

**Existing guard limitations covered:** owned holders are excluded from its
final idle calculation, and group cleanup can return when the direct child
exits. The outer launcher records unfiltered all-holder/whole-boot state after
every guard result or exception, performs bounded cleanup only for the tracked
child's owned group/session when needed, then obtains another strict final
observation. Forced cleanup, observation errors or surviving clients prevent
acceptance. Guard status alone cannot pass.

Assertions remain enabled. Identity/metadata verification precedes one reserved
attempt; Chromium stays unprivileged under the real `avd` lease. Acceptance
requires inner completion, normal browser exit and clean final state. The
90-second guard deadline can incur bounded observation/cleanup overhead.

**Disposition:** no confirmed blocker remained in these exact launch files

review's stable kernel/root-device assumptions. This review did not establish
